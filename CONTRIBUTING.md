# Участие в fnport

Помочь можно отчетом о подключении, воспроизводимым описанием ошибки, исправлением
документации или pull request. Перед участием прочитайте [правила общения](CODE_OF_CONDUCT.md).

## Сообщение об ошибке

Проверьте [последний релиз](https://github.com/YUNGSLXRD/fnport/releases/latest)
и поищите похожее обращение среди issues. Если проблема уже описана, дополните
существующую ветку своим отчетом.

В новом issue укажите:

- Версию fnport, систему, провайдера и город.
- Как повторить проблему, какой результат ожидался и что произошло.
- Точный текст ошибки и режим игры: королевская битва, творческая карта или другой.
- Отчет проверки провайдера и журнал после неудачной попытки.

В Windows журнал `fnport.log` находится рядом с программой. В OpenWrt журнал доступен
на странице fnport в LuCI. Не запускайте проверку провайдера перед каждой попыткой:
частые пробы могут повлиять на ответы серверов.

Файл `fnport.json`, ссылки подписок и конфигурации VPN прикладывать не нужно.
Перед публикацией журналов уберите ключи, пароли и другие личные данные.
О возможных уязвимостях сообщайте по [Security policy](SECURITY.md).

Автоответы и напоминания публикуются от `github-actions[bot]`. После 10 дней
неактивности бот напомнит об обращении, еще через 4 дня закроет его, если новых
сообщений нет. Новое сообщение снимает отметку неактивности при следующей проверке.
Метки `bug`, `keep-open` и `security` исключают issue из автоматического закрытия.
Закрытие по неактивности не означает, что ошибка исправлена. Если проблема актуальна,
добавьте свежие данные и попросите переоткрыть обращение.

## Изменения кода

Создайте отдельную ветку от `main` и опишите конкретный сценарий до и после изменения.
Не добавляйте сборки, кеши, личные настройки, ключи и журналы в коммит.

Для кода Windows нужны Go 1.24.7 или совместимая более новая версия и `gofmt`.
Проверки запускаются из корня репозитория:

```sh
go -C windows vet ./...
go -C windows test ./...
```

Проверки с настоящим sing-box используют `FNPORT_TEST_SING_BOX`, путь к закрепленной
версии ядра. Официальная Windows-сборка выполняется через `windows/build-release.sh`.
Полная сборка также проверяет Windows-код, зависимости и комплектность архива.

Изменения OpenWrt проверяются в SDK и отдельном тестовом окружении. Скрипты
`tests/validate-openwrt.sh` и `tests/openwrt-install.sh` предназначены для изолированного
тестового rootfs, не для рабочего роутера. Укажите в PR, какие проверки выполнены,
а какие провести не получилось. Полные сборки запускаются в GitHub Actions для PR,
тегов релизов и вручную.
