# Состояние проекта и что дальше

Рабочие заметки для разработки: что готово, что известно по тестам, что можно исправить.
Обновлено 28 октября 2026, последняя версия — **0.6.2** (в 0.6.2 уже сделаны пункты 1, 2 и часть 3–4 из списка ниже).

## Где что лежит

| Путь | Что это |
|---|---|
| `fnport/` | Пакет для OpenWrt: служба `fnportd.uc` (ucode), проверка провайдера `fnport-check.uc`, обновление `fnport-update.uc`, фейки `quic_initial_*.bin` |
| `luci-app-fnport/` | Веб-интерфейс LuCI (`check.js`, `settings.js`, `status.js`), перевод `po/ru/fnport.po` |
| `image/` | Образ диска x86-64 с fnport (виртуальная машина вместо роутера) |
| `windows/` | Программа для Windows на Go: движок (`fnport/engine.go`, `prober.go`, `tcp.go`), проверка (`check.go`, `epic.go`), WARP (`warp.go`, `internal/awgnet`), окно на Gio (`ui.go`, `flags.go`) |
| `windows/probe/` | Утилита-зонд для исследований (в релиз не входит) |
| `.github/workflows/build.yml` | CI: пакеты 24.10/25.12, образ, программа для Windows; на тег `v*` прикладывает файлы к релизу |

## Что готово

**Роутер (OpenWrt).** Пакет, LuCI, установщик-обновлятор, кнопка «Обновить» в LuCI. Подбор портов
по рукопожатию Unreal, фейк QUIC с белым именем и коротким TTL, перевод замёрзших соединений, запасные фейки,
ожидание, где заморозки нет. Проверка провайдера: заморозка, подбор TTL, перебор фейков, отличие потерь
пакетов от заморозки (ответы на пакеты после 25-го).

**Программа для Windows (0.6.1).** Адаптер Wintun, движок как на роутере, без WinDivert. Вкладки: главная
(пинг до маяков с флагами, счётчики, карточка WARP), сводка, журнал, WARP, настройки. Проверка провайдера:
порт, заморозка, TTL, сервисы Epic напрямую (вход, сервисы Fortnite, загрузка, подбор матчей, пати, чат),
потери против заморозки, поиск TTL ниже, если фейк убивает, предложение включить выключенный фейк.
Автоподстройка TTL во время игры: если два раунда нет годного порта — перебор соседних TTL (−1, +1, −2, +2,
−3, −4), берётся первый, с которым порт прошёл.

**WARP для сервисов Epic (Windows).** Ключ одной кнопкой (запрос и отпечаток TLS как у wgcf, ClientHello
делится на сегменты и TLS-записи — провайдеры режут `api.cloudflareclient.com` по имени) или вставка своего
конфига WireGuard/AmneziaWG. Туннель AmneziaWG (`amneziawg-go`) со своим TCP-стеком (`internal/awgnet`)
и UDP через физический адаптер; перед первым пакетом и после 20 с тишины — фейк fnport с текущим TTL.
Выбор адреса: все диапазоны (188.114.96–99, 162.159.192), проверка объёмом 256 КБ через cdnjs, до двух портов
на адрес, выход за границей предпочтительнее российского. Режимы: выключен / только то, что напрямую
не открывается или замерзает / всегда. Заморозка напрямую ловится по остановке посреди TLS-записи или
запросу без ответа 10 с; после первого такого сайта всё из списка идёт через WARP, сеть запоминается
на 3 дня в `%LOCALAPPDATA%\fnport\warp-state.json`. Выбор сайтов — по SNI, плюс маршруты /32 к адресам
сайтов из списка.

## Что известно по тестам

- **Маяки не равны игровым серверам.** Маяки Epic могут отвечать 30/30, а игровой сервер в том же городе
  замораживает порты. «Заморозки нет» в проверке — только про маяки.
- **Граница TTL плавает за вечер** (Дом.ру): днём фейк с TTL 4 снимал заморозку, ночью убивал, потом так же
  3, потом работал только 2. Отсюда автоподстройка.
- **Потери против заморозки** (SkyNet, Wi-Fi): 23 из 30 при любом TTL — это потери, не заморозка.
- **Сервисы Epic напрямую** у части провайдеров замерзают посреди ответа (3–40 КБ): «не удалось загрузить
  ключи ресурсов», пустой магазин, заглушки в шкафчике. Через WARP работают.
- **WARP:** без фейка туннель замерзает всегда; с фейком работает. Выход в Москве (DME) — большие загрузки
  вставали; Хельсинки (HEL) — 75–82 Мбит/с. `loc` в trace Cloudflare — страна адреса WARP (всегда страна
  пользователя), страну выхода даёт `colo`. Через WARP `speed.cloudflare.com` отвечает 403, cachefly — пустым
  200, поэтому проверки через WARP идут на cdnjs.
- Мобильный интернет МегаФон и Т2 — без заморозки (октябрь 2026).

## Что можно исправить или доработать

По убыванию пользы.

1. **«Применить» нет — объяснить.** Если проверке нечего менять, писать в итоге: «Настройки подходят —
   включайте fnport на главной». Сейчас пользователи ищут кнопку.
2. **Понятная ошибка без `wintun.dll`.** Вместо «Error loading wintun.dll» — «Рядом с fnport.exe нет
   wintun.dll: распакуйте архив целиком в обычную папку; если файл пропадает — проверьте антивирус».
   Можно проверять файл при запуске и показывать на главной.
3. **Зависание на «применении параметров региона».** Разобраться, при каком режиме (WARP вкл/выкл, сеть
   с заморозкой сервисов) это повторяется. Добавить в журнал строку о запросе к сервису Epic, который висит
   дольше N секунд, с именем сайта.
4. **WARP: проверить на живой сети** то, что сделано в последних сборках и не подтверждено: фейк после 20 с
   тишины, переход «всё через WARP» после одного сайта, запрос без ответа 10 с. Возможные ложные срабатывания —
   долгие соединения (чат, websocket), которые законно молчат; при них всё Epic уходит в WARP раньше времени.
5. **WARP: ключ живёт в `fnport.json` рядом с программой.** При распаковке новой версии в другую папку ключ
   регистрируется заново. Перенести ключ (как `warp-state.json`) в `%LOCALAPPDATA%\fnport` или подхватывать
   из старой копии.
6. **WARP: «сначала напрямую» стоит 5 секунд** на первое соединение к каждому заблокированному сайту. В сети,
   запомненной как замерзающая, это уже обходится; можно сократить таймаут или проверять параллельно.
7. **Роутер: автоподстройка TTL**, как в программе для Windows (сейчас только в `prober.go`). Перенести логику
   в `fnportd.uc`: перебор соседних TTL, когда два раунда нет годного порта.
8. **Роутер: проверка ищет TTL ниже**, когда маяки чистые, а фейк убивает (в Windows сделано, в `fnport-check.uc`
   нет).
9. **README: вопрос про кик «Forbidden Tool»** — только когда случай Zeri4ez подтвердится (что именно мешало).
   Не писать догадки как факт.
10. **Тест движка с имитацией ТСПУ:** сервер-эхо, который пропускает поток только при фейке с нужным TTL
    (на loopback TTL не виден — нужен другой способ, например подставной `sendFake`).

План до 1.0 (после этого — только поддержка): приложение для Android без root (VpnService), TCP-фейк
для сервисов Epic на роутере, другие игры (Apex, Dead by Daylight — в работе не начаты).

## Как собирать и проверять

- **Программа для Windows:** `windows/build.sh <версия>` (нужны Go и zip, работает на macOS и Linux),
  результат в `windows/dist/`. Перед сборкой — `go vet ./...`, `GOOS=windows go vet ./...`, `go test ./...`
  (это делает и сам скрипт).
- **Версия Go:** в `go.mod` стоит `go 1.24.4`, CI собирает на Go 1.24.7 с `GOTOOLCHAIN=local`. Новый Go
  при `go get`/`go mod tidy` поднимает строку `go` и версии `golang.org/x/*` — после этого CI падает. Проверять:
  `GOTOOLCHAIN=go1.24.7 go vet ./...`. gVisor закреплён через `replace` (версии из основной ветки gVisor
  не собираются go-инструментами).
- **Предпросмотр окна без Windows:** `FNPORT_PREVIEW_DIR=<папка> go test -tags preview -run TestPreview ./fnport`
  рисует вкладки в PNG.
- **Скрипты роутера:** синтаксис ucode проверяется `ucode -c -o /dev/null файл.uc` на любом OpenWrt.
  LuCI: `node --check check.js`. Строки с апострофом внутри `_('…')` в одинарных кавычках ломают страницу.
- **CI:** запускается только вручную (`gh workflow run build.yml --ref <ветка>`), на теги `v*` и PR.
- **Тестовые сборки** для пользователей: ветка `test-builds`, ссылка
  `https://github.com/YUNGSLXRD/fnport/raw/test-builds/<файл>.zip`.
- **Релиз:** версия в `fnport/Makefile` и `luci-app-fnport/Makefile`, раздел в `CHANGELOG.md`, зелёный CI
  на ветке, слияние в `main`, `gh release create vX.Y.Z` — CI сам приложит файлы.

## Правила проекта

- Без подписей ИИ в коммитах, PR и релизах.
- Заметки к релизам и CHANGELOG — коротко и простым языком, без внутренностей.
- Не писать, какие ошибки Fortnite (#1, #3, #5…) fnport исправляет или нет; писать, что измерено.
- Не советовать VPN как решение для самой игры. Белый IP — только как обычно платный последний вариант.
- Секреты (ключи, конфиги, подписки, пароли) не показывать и не коммитить.
- Релизы, публикации, сообщения в issues — только после явного согласия владельца.
- Частые пробы ТСПУ «наказывает»: не запускать проверки подряд без нужды.
