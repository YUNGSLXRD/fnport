# Нет роутера с OpenWrt?

fnport работает только на устройстве с OpenWrt, через которое игровой ПК выходит в интернет.
**На самом Windows-ПК его не запустить:** чтобы выбирать исходящий порт игры, нужен сетевой драйвер,
а такие драйверы (тот же WinDivert у запрета) Easy Anti-Cheat выгружает. Поэтому нужно отдельное
устройство с OpenWrt, но совсем не обязательно выбрасывать свой роутер.

Какой вариант подходит вам:

![Какой вариант выбрать](img/no-openwrt-choose.svg)

## Вариант 1. Прошить свой роутер в OpenWrt

![Вариант 1: свой роутер прошит в OpenWrt](img/no-openwrt-option1.svg)

1. **Проверьте модель.** Откройте [firmware-selector.openwrt.org](https://firmware-selector.openwrt.org/)
   и введите модель роутера с наклейки на дне, включая ревизию (например, `v2`). Нужна версия 24.10 или новее.
   Если модели нет, этот вариант не подойдёт: переходите к варианту 2.
2. **Прочитайте страницу своей модели** в [списке устройств OpenWrt](https://openwrt.org/toh/start).
   Способ прошивки у разных моделей разный: где-то хватает загрузить файл в веб-интерфейсе роутера,
   а где-то нужны особые шаги. Делайте строго по инструкции для своей модели.
3. **Перепишите настройки интернета** со старой прошивки: тип подключения (PPPoE, IPoE/DHCP),
   логин и пароль PPPoE из договора с провайдером. Они понадобятся после прошивки.
4. **Прошейте роутер** по инструкции из шага 2.
5. В LuCI (`http://192.168.1.1`) задайте пароль, настройте интернет (**Сеть → Интерфейсы → wan**) и Wi-Fi.
6. Поставьте fnport по разделу [«Установка»](../README.md#установка).

> Прошивка — это риск: при ошибке роутер может перестать включаться, гарантия обычно теряется.
> Если роутер нужен для работы или учёбы и запасного нет, лучше вариант 2.

## Вариант 2. Добавить устройство с OpenWrt, свой роутер оставить

Подходит для Keenetic, роутеров провайдера и любых моделей без OpenWrt.
Понадобится недорогой роутер, который поддерживает OpenWrt (fnport проверялся на **Xiaomi AX3000T**),
или мини-ПК / Raspberry Pi с двумя сетевыми портами. Проверить модель перед покупкой можно так же,
через [firmware-selector.openwrt.org](https://firmware-selector.openwrt.org/). Хватит 128 МБ памяти.

**Мини-ПК или старый компьютер с двумя сетевыми портами** не нужно прошивать по инструкции модели:
в [релизе](../../../releases/latest) есть готовый образ диска с OpenWrt и fnport (`fnport-…-x86-64.vhd.zip`).
Распакуйте его и запишите `.vhd` на флешку или SSD программой [Rufus](https://rufus.ie/) (выбрать файл →
«Старт», режим DD), загрузите компьютер с неё. Первый сетевой порт (`eth0`) станет LAN с адресом
`192.168.2.1`, второй (`eth1`) — WAN, остальные тоже будут LAN. Если перепутались, поменяйте кабели местами.
Дальше LuCI на `http://192.168.2.1`: задайте пароль, при PPPoE настройте **Сеть → Интерфейсы → wan**,
добавьте игровой ПК в «Устройства» fnport и включите его.

**2а. Рекомендуется: OpenWrt — главный роутер, старый раздаёт Wi-Fi**

![Вариант 2а: OpenWrt главный, старый роутер раздаёт Wi-Fi](img/no-openwrt-option2a.svg)

1. **Узнайте настройки интернета** в старом роутере: тип подключения и, если это PPPoE, логин и пароль.
   В Keenetic они на странице **Интернет → Проводной**. Если провайдер привязывает доступ к MAC-адресу,
   запишите MAC старого роутера.
2. **Подготовьте роутер с OpenWrt** (прошейте по шагам из варианта 1, если он не с OpenWrt «из коробки»)
   и настройте в нём интернет: **Сеть → Интерфейсы → wan**. Для PPPoE выберите протокол «PPPoE»
   и введите логин и пароль. Если нужен MAC старого роутера, укажите его там же
   («Дополнительные настройки → Переопределить MAC-адрес»).
3. **Переключите старый роутер в режим точки доступа**, чтобы он только раздавал Wi-Fi:
   - Keenetic: **Общие настройки → Изменить режим работы → Точка доступа/Ретранслятор**.
     У моделей с переключателем на корпусе — переключателем
     ([инструкция Keenetic](https://support.keenetic.ru/eaeu/giga/kn-1010/ru/16715-system-operating-modes.html));
   - другие роутеры: режим «Точка доступа» / «Access Point», если он есть. Если нет, выключите на старом
     роутере DHCP-сервер и подключайте его к OpenWrt только через LAN-порт, не через WAN.
4. **Переподключите кабели:** кабель провайдера — в WAN-порт роутера с OpenWrt; LAN-порт OpenWrt — в любой
   порт старого роутера; игровой ПК — кабелем в OpenWrt (можно и в старый роутер, трафик всё равно пойдёт через OpenWrt).
   Названия и пароли Wi-Fi останутся прежними.
5. Поставьте fnport по разделу [«Установка»](../README.md#установка) и добавьте в «Устройства» IP игрового ПК.

**2б. Проще: OpenWrt за старым роутером**

Если не хочется трогать настройки интернета, роутер с OpenWrt можно поставить после старого:

![Вариант 2б: роутер с OpenWrt за старым роутером](img/no-openwrt-option2b.svg)

Кабель от LAN-порта старого роутера идёт в WAN-порт роутера с OpenWrt, игровой ПК подключается к OpenWrt.
Учтите:
- старый роутер ещё раз меняет адреса (двойной NAT). fnport сработает, только если старый роутер
  сохраняет исходящий порт. **Проверено:** обычный роутер (не OpenWrt) и роутер на OpenWrt порт сохраняют,
  игра через такую цепочку загружается. Какой-нибудь роутер может и менять порт: если fnport пишет,
  что порт найден, а соединения всё равно замерзают, дело, скорее всего, в этом;
- до ТСПУ дальше, поэтому TTL фейка нужен больше. Подберите его кнопкой **«Проверить провайдера»**
  в LuCI роутера с OpenWrt (Службы → fnport → Проверка провайдера): она меряет путь оттуда, где стоит fnport.
  Если подбирать вручную, прибавьте по 1 за каждый роутер между fnport и провайдером
  (один старый роутер — `fake_ttl` = 4, два — 5);
- если ваш роутер проверен в такой схеме, напишите в issues модель — добавим в список.

## Вариант 3. OpenWrt в виртуальной машине на игровом ПК

![Вариант 3: OpenWrt в виртуальной машине на игровом ПК](img/no-openwrt-option3.svg)

Можно запустить OpenWrt в VirtualBox или Hyper-V и направить через неё игровой трафик ПК.
**Проверено:** fnport в виртуальной машине пропускал игру у двух разных провайдеров, в том числе за обычным
роутером. Виртуальную машину нужно держать включённой во время игры.

### Готовый образ

В [релизе](../../../releases/latest) лежит `fnport-…-x86-64.vhd.zip`: OpenWrt с уже установленным и включённым fnport.
Внутри диск `.vhd` и скрипт `fnport-routes.cmd`. В виртуальной машине образ при первом запуске настраивается
сам: LAN `192.168.56.2`, ПК получает адрес без шлюза (интернет у ПК не пропадёт, даже если машина выключена),
fnport включён для ПК, TTL фейка 4.

1. **Распакуйте** архив в папку, где он будет жить (диск растёт, держите его не во «Временных файлах»).
2. **Создайте машину.**
   - **VirtualBox:** «Создать», тип «Linux», версия «Other Linux (64-bit)», 256 МБ памяти,
     «Использовать существующий виртуальный жёсткий диск» → `.vhd`. В настройках машины, раздел «Сеть»:
     **адаптер 1** — «Виртуальный адаптер хоста» (host-only), **адаптер 2** — «Сетевой мост» на адаптер,
     через который ПК выходит в интернет. В «Файл → Инструменты → Менеджер сетей» у адаптера хоста должен быть
     адрес `192.168.56.1`, а его DHCP-сервер — выключен.
   - **Hyper-V** (Windows Pro): в «Диспетчере виртуальных коммутаторов» создайте внутренний и внешний коммутаторы.
     Новая машина **1-го поколения**, 256 МБ памяти, существующий диск `.vhd`. Сетевые адаптеры: первый —
     во внутренний коммутатор, второй — во внешний. Hyper-V пока проверен только по документации, напишите
     в issues, получилось ли.
3. **Запустите машину** и через минуту откройте `http://192.168.56.2`. LuCI попросит задать пароль: задайте.
4. **Маршруты.** Запустите `fnport-routes.cmd` двойным щелчком, разрешите ему права администратора и выберите
   «2 — включить насовсем» (или «1» — до перезагрузки, чтобы сначала попробовать). Через машину пойдёт только
   трафик к AWS в Европе, остальное как раньше. Если машина не запущена, скрипт ничего не изменит.
   Выключить: тот же скрипт, пункт «3».
5. **TTL фейка.** В LuCI машины: Службы → fnport → Проверка провайдера → «Проверить провайдера»,
   и «Применить TTL», если предложит.

Сбросить машину к настройкам из образа: `firstboot -y && reboot` в её консоли.
Для VMware диск нужно сконвертировать: `qemu-img convert -f vpc -O vmdk fnport.vhd fnport.vmdk`.

### Вручную

Если хочется собрать машину самому:

1. **Образ.** На [firmware-selector.openwrt.org](https://firmware-selector.openwrt.org/) выберите
   «Generic x86/64» и скачайте `combined-efi (squashfs)`. Распакуйте `.img.gz` и превратите образ в диск
   VirtualBox: `VBoxManage convertfromraw openwrt.img openwrt.vdi --format VDI`.
2. **Виртуальная машина** — как в шаге 2 выше, диск `openwrt.vdi`.
3. **Сеть.** В консоли виртуальной машины (OpenWrt на x86 сам настраивает только LAN):
   ```sh
   uci set network.lan.ipaddr='192.168.56.2'
   uci set network.wan=interface
   uci set network.wan.device='eth1'
   uci set network.wan.proto='dhcp'
   # ПК получит адрес, но не шлюз и DNS: иначе Windows отправит через машину весь трафик,
   # и без неё у ПК «пропадёт интернет»
   uci add_list dhcp.lan.dhcp_option='3'
   uci add_list dhcp.lan.dhcp_option='6'
   uci commit && reboot
   ```
4. **fnport.** Откройте LuCI машины (`http://192.168.56.2`), задайте пароль, поставьте fnport
   [установщиком](../README.md#установка) и добавьте в «Устройства» адрес ПК на адаптере host-only
   (`ipconfig`, в VirtualBox это `192.168.56.1`).
5. **Маршруты и TTL** — как в шагах 4 и 5 выше (`fnport-routes.cmd` лежит в [`image/`](../image/fnport-routes.cmd)).

Если у ПК всё же пропал интернет: удалите маршрут по умолчанию через машину,
`Remove-NetRoute -DestinationPrefix 0.0.0.0/0 -NextHop 192.168.56.2` (команда `route delete`
маршрут, выданный по DHCP, не удаляет), и проверьте шаг 3.

## Keenetic без второго устройства

Отдельная версия fnport для Keenetic (через Entware) в планах. На Keenetic нет `nftables`,
на которых работает fnport, поэтому её придётся переделать. Если у вас Keenetic и вы готовы помочь
с проверкой, напишите в issues.
